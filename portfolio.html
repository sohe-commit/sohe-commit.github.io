문제

매체팀이 매주 평균 5개 이상 지면의 단가 조정을 요청했고, 운영자는 화면 3개를 오가며 단가를 하나씩 고쳤습니다. 같은 성과를 보고도 운영자마다 조정 결과가 달라질 수 있었습니다.

판단

매체팀·운영팀이 보는 지표를 확인하고, 연구원과 데이터가 충분한지 검토한 뒤 지면 등급을 설계하기로 했습니다. 자동화하되, 사람이 결과를 확인하고 개입할 수 있는 구조는 남기기로 했습니다.

실행

기존 시간대·타겟팅 등급에 새로 설계한 지면 등급(12등급 + NA)을 더해 판단 단위를 정의했습니다. 실시간 입찰(RTB) 지면은 대상에서 빼고, 등급별 가중치 수정 권한은 의사결정권자 6명으로 제한했습니다. 개발·송출 담당자와 실제 광고를 송출해 과금 반영까지 확인했습니다.

결과

판단 화면 3개 → 1개 지면별 수정 → 등급 단위 일괄 조정 세션 ROAS +13.7% CTR +8.3%

CPC 자동화 적용 광고주의 배포 전후 2주 일평균 비교입니다. 세션 ROAS 125% → 142%, CTR 2.07% → 2.24%.

02 · 광고주센터 리뉴얼(모비온 4.0) · 2025.05 – 2026.02 · 서비스 기획 · PM

성과를 먼저 보고, 필요한 작업으로 바로 이동하게 했습니다

문제

정기 고객 만족도 조사에서 대행사는 '원하는 메뉴를 찾기 어렵다'는 의견을 지속적으로 냈고, 운영팀 인터뷰에서는 '계정 성과를 빠르게 파악하기 어렵다'는 의견이 나왔습니다. 랜딩 URL 등록도 웹링크와 딥링크로 나뉘어 있어, 캠페인마다 같은 딥링크를 다시 만들어야 했습니다.

판단

운영 필수도·페이지 PV·개발 공수를 기준으로 4개 팀과 범위를 합의했고, 함께 쓰이는 기능은 한 번에 배포해야 흐름이 이어진다고 판단했습니다. 랜딩 URL 등록은 리뉴얼 범위에 없었지만, 광고를 운영하며 직접 느낀 불편이었고 운영팀 인터뷰에서도 통일 의견이 나와 하나로 합쳐야 한다고 판단했습니다.

실행

Google Ads의 계층 구조를 참고해 IA를 다시 짜고, 대시보드에 핵심 지표와 추이를 먼저 배치했습니다. 개발팀을 설득해 랜딩 URL 등록을 소재 등록 안으로 넣고, 기존 광고가 정상 작동하도록 송출 정책과 DB 변경 요구사항을 정의했습니다.

결과

성과 확인 60분 → 25분 캠페인 등록 40% 단축 등록 과정 2개 → 1개

시간 수치는 내부 테스트 시나리오 기준입니다(캠페인 등록은 외부 사용자 권한으로 테스트).

03 · 보고서 에디터 · 2025.09 – 2025.12 · 서비스 기획 · PM

바뀐 송출 구조에 맞춰 보고서를 다시 설계했습니다

문제

송출 구조가 캠페인·광고그룹·소재그룹으로 바뀌었지만, 보고서에서는 소재그룹 성과를 볼 수 없었습니다. 템플릿 생성과 수정의 구분도 명확하지 않았습니다.

판단

송출 구조와 보고서의 데이터 구조를 먼저 일치시키고, 템플릿 흐름은 사용자 행동에 맞게 다시 짜는 것을 핵심 과제로 잡았습니다.

실행

송출할 때 소재그룹 ID를 필수로 전달하도록 요구사항을 정의했습니다. 템플릿 생성·수정·불러오기 흐름을 나누고, 컬럼 재배열과 프리셋을 제공했습니다. 출시 후 피드백을 받아 보고서에는 소재명만 남겼습니다.

결과

소재그룹 단위 조회 가능 개편 첫 달 500건 생성 이후 월평균 120건 고객사 사용 안내 문의 감소

생성 건수: 보고서 템플릿 생성 기준, 사내 로그(월평균은 2026.01 – 05). 문의 감소는 출시 후 영업팀을 통해 확인했습니다.
